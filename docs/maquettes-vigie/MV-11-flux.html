Ce que montre l’écran

Puis le même en tableau, ce que les alertes ont déclenché, et les provenances les plus actives.

À créer

En D3 : la route /flux (periode, alerte) ; les agrégats par flux, calculés une fois par minute à partir des événements, des signaux (vigie_signal) et des alertes, sans relire le journal (une table de comptes par minute, que la vue somme) ; l’origine de chaque événement (une règle par type : visiteur, réseau listé, compte de l’admin, hors application, Zitadel, la Vigie) ; le rendu SVG serveur, transcrit de dr-tmp/vigie-mq/flux.py (mêmes étapes, mêmes arrondis) ; le surlignage d’une alerte ; le lien « Voir son flux » sur la fiche d’une alerte ; les provenances (ASN et pays sont dans les lignes de la bordure).

Écarts avec le lexique et le code

Le lexique dit « 24 h » par défaut ; la page dit « aujourd’hui, depuis 0 h », comme le journal (MV-03), pour que les 319 événements soient les mêmes. Les réponses et les messages, que le § 3.17 range parmi les issues, sont sous le diagramme : ils ne se comptent pas en événements. La répartition des 319 par origine et par chemin n’existe pas au lexique avant MV-11 ; elle suit les sources de MV-03 (site 241, bordure 38, Zitadel 19, Vigie 21) et les occurrences des alertes (#409 37, #405 12), et le lexique la reprend (§ 3.17, données).

Styles à embarquer (D3). La console dépend des classes de l’admin refondue (liste-a, champ-a, note-a, kv-a, plier), qui n’existent pas encore dans public/admin/admin.css : elle embarquera ces styles avec vigie.css (lexique § 3.14, point 18).
